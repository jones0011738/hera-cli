# Stable Diffusion in Hera

Hera can generate images from text prompts using a **self-hosted Stable
Diffusion** server. Like chat, vision, and embeddings, it runs on the box and is
reached through the identity proxy — no third-party API, no data leaving the
host.

The capability shows up in **every surface**:

| Surface | How you use it |
| --- | --- |
| CLI REPL / `-p` | Ask for an image, or the model calls the `generate_image` tool |
| `--serve` (VS Code) | Same tool, same approval prompt |
| `--acp` (Zed etc.) | Same tool, permission via `session/request_permission` |
| `--tui` | Same tool; approval via a modal |
| Sub-agents | A delegated `task` can generate images too |
| **Web chat** (Open WebUI) | The image button under the prompt box |

## Architecture

```
client ──Bearer <OWUI key>──▶ auth-proxy (:8090)
                                 │  validates the key, then routes by path:
                                 │    /v1/chat/completions   → qwen-server
                                 │    /v1/images/generations → sd-server  ◀── new
                                 └────────────────────────────────────────▶
                              sd-server (:1234, internal only)
                              stable-diffusion.cpp + SDXL base 1.0
```

`sd-server` is `stable-diffusion.cpp` (ggml — the same lineage as the llama.cpp
chat/vision/embed servers). It exposes an **OpenAI-compatible**
`POST /v1/images/generations` that returns `data[].b64_json`. It has **no auth of
its own**, so it is never published on a host port; the auth-proxy is the only
way to reach it and it validates the caller's Open WebUI key first — exactly like
`embed-server`.

Model: **SDXL base 1.0** (`/opt/models/sd/sd_xl_base_1.0.safetensors`) with the
**fp16-fix VAE** (`sdxl.vae.safetensors` — the stock SDXL VAE produces NaNs in
fp16). Pinned to GPU 1 by default.

## Using it from the CLI

Just ask:

```
› draw a watercolor fox curled up asleep, soft morning light, and save it as fox.png
```

or call the tool directly (it's what the model uses under the hood):

`generate_image`
| Arg | Meaning |
| --- | --- |
| `prompt` *(required)* | What to draw |
| `path` | Where to save the PNG (default: a slug of the prompt in the cwd) |
| `size` | `WIDTHxHEIGHT`, e.g. `1024x1024` (default) or `1024x768` |
| `steps` | Sampling steps (optional; server default otherwise) |
| `cfg_scale` | Prompt-adherence / CFG scale (optional) |
| `negative_prompt` | What to avoid (optional) |
| `seed` | Seed for reproducibility; omit for random |

It writes the PNG and returns `saved image (<bytes>) to <path>`. Generating an
image is a side effect, so it goes through the normal approval prompt (or runs
straight through in YOLO mode).

Under the hood the tool sends dimensions in the OpenAI `size` field and passes the
SD-native controls (steps, CFG, negative prompt, seed) via an
`sd_cpp_extra_args` block embedded in the prompt, which the server parses out and
removes before generating.

## Using it from the web chat

Open WebUI's image generation is enabled and pointed at the auth-proxy (OpenAI
engine). Type a prompt and click the image icon; the picture is generated by the
same `sd-server`.

## Configuration

CLI (env or `~/.config/hera/config`):

| Variable | Default | Purpose |
| --- | --- | --- |
| `HERA_IMAGE_URL` | `HERA_API_URL` | Base URL for the images endpoint (`/images/generations` is appended) |
| `HERA_IMAGE_MODEL` | `sd-cpp-local` | Model id sent in the request (sd-server reports a fixed id) |

Server (`docker-compose.yml`):

| Variable | Default | Purpose |
| --- | --- | --- |
| `SD_VISIBLE_DEVICES` | `1` | Which GPU `sd-server` uses |
| `IMAGE_UPSTREAM` (proxy) | `http://sd-server:1234` | Where the proxy routes `/v1/images/*` |

To swap models, drop new weights in `/opt/models/sd/` and update the `sd-server`
`command:` (`-m` / `--vae`) in `docker-compose.yml`, then
`docker compose up -d sd-server`.

## Bringing it up

```bash
# One-time: fetch the weights (~7 GB + ~320 MB)
mkdir -p /opt/models/sd
curl -fL -o /opt/models/sd/sd_xl_base_1.0.safetensors \
  https://huggingface.co/stabilityai/stable-diffusion-xl-base-1.0/resolve/main/sd_xl_base_1.0.safetensors
curl -fL -o /opt/models/sd/sdxl.vae.safetensors \
  https://huggingface.co/madebyollin/sdxl-vae-fp16-fix/resolve/main/sdxl.vae.safetensors

# Start the server + refresh the proxy/web so they pick up the new route/config
docker compose up -d sd-server
docker compose up -d --no-deps auth-proxy open-webui

# Smoke test (through the proxy, with a real OWUI key)
curl -s http://localhost:8090/v1/images/generations \
  -H "Authorization: Bearer $OWUI_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"sd-cpp-local","prompt":"a lighthouse at dusk","size":"1024x1024"}' \
  | python3 -c 'import sys,json,base64; open("out.png","wb").write(base64.b64decode(json.load(sys.stdin)["data"][0]["b64_json"])); print("wrote out.png")'
```

First generation after start is slower (model load); subsequent ones are fast.
